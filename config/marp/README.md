# marp のテーマ `modern` の書き方

`theme: modern` のスライドで使える、スライドの種類、部品、記法をまとめる。色や大きさの決まりは、デザインシステム「modern」の README (`config/design-system/project/README.md`) にある。

## 始め方

```markdown
---
marp: true
theme: modern
paginate: true
---
```

変換は `marp` コマンドで行う (`marp slides.md`、`marp --pdf slides.md`、`marp --pptx slides.md`)。テーマと拡張は `~/.marprc.yml` が指しているので、指定は要らない。

この `marp` は、`--config ~/.marprc.yml` を足す zsh の関数 (`modules/zsh.nix`)。スクリプトや `timeout` 越し、AI エージェントから呼ぶときは、関数を通らず、標準入力も待ってしまうので、次の形で呼ぶ。

```sh
command marp --config "$HOME/.marprc.yml" --no-stdin slides.md --pdf
```

## 効く環境

| 書き方 | `marp` コマンド | VS Code のプレビュー、ほかの PC |
|---|---|---|
| スライドの種類 (`_class`)、色の class、HTML で書いた部品、目次 | 効く | テーマの CSS を読ませれば効く |
| `:::` の記法、章の番号、フッターの自動反映 | 効く | 効かない (`:::` が文字のまま出る) |
| 図の線 | PDF、PNG、PPTX、HTML で描かれる | 描かれない |

`:::` の記法、章の番号、フッター、図の線は、この dotfiles が配るエンジンの拡張 (`~/.config/marp/engine/`) が行う。

## スライドの種類

スライドの先頭に `<!-- _class: 名前 -->` を書く。空白で区切って、複数を並べられる。

| class | 使い道 |
|---|---|
| (なし) | ふつうのスライド。最初の `#` が、左上の題になる |
| `title` | 表紙。中央揃え |
| `section` | 章の扉。`##` で章の名前を書く。番号は自動で付く |
| `toc` | 目次。番号付きリストを並べる (6 項目までは 1 列、7 項目からは 2 列) |
| `no-header` | 題を出さない |
| `align-center` | 中身を縦の中央に置く |
| `small-text` | 文字と行間を約 0.72 倍にする。表や補足のスライド用 |
| `black` | 黒い地。動画や写真を全面に見せるとき |
| `image` | 画像だけを大きく見せる |
| `content-image` | 文の下に画像を置く |
| `content-image-right`、`content-image-left` | 文の右 (左) に画像を置く。既定は半々。`content-30`〜`content-80` で文の幅を変える |
| `column-layout` | 2 列に分ける。列は `<div class="column">` で囲む |
| `text-center`、`h1-text-center`〜`h6-text-center`、`all-text-center` | 中央揃え |

## 表紙、目次、章の扉、フッター

```markdown
<!-- _class: title -->

# 発表の題

### 名前

---

<!-- _class: toc -->

# 目次

1. 研究背景・目的
2. 関連研究
3. 提案手法

---

<!-- _class: section -->

## 研究背景・目的

---

# 背景

ここから次の章の扉まで、フッターに「1. 研究背景・目的」が入る。
```

- 目次の番号は、番号付きリストの番号ではなく、CSS が上から順に振る。
- 章の扉の番号は、扉が出てきた順に 1 から振られる。目次の順番と、扉の順番を揃えること。
- フッターは、章の扉の見出しから作られる。表紙と、章の扉そのものには入らない。
- あるスライドだけフッターを変えるには `<!-- _footer: 文字 -->`、消すには `<!-- _footer: "" -->` と書く。
- 番号を自分で決めたいときは、見出しに `## <span class="toc-num">3.</span>考察` と書く。以降の番号は、そこから続く。
- 章の扉の見出しは `##` でも `#` でも、同じ位置と大きさで出る。
- スライドの題 (最初の `#`) は 1 行の前提で場所を取ってある。全角でおよそ 19 文字を超えると 2 行になり、本文に重なる。超える見込みの題には、変換のときに `[modern] スライド N の題…` という警告が出る。

## 色

文中の語に色を付けるには、`<span class="blue">語</span>` と書く。使える名前は `red`、`orange`、`yellow`、`green`、`turquoise`、`blue`、`purple`、`pink`。

強調は `blue`、否定や問題は `red` を使う。ほかの色は、分類を区別するときだけに使う。`yellow` は文字にするとオリーブ色に見えるので、「黄」を伝えたいときは `orange` を使う。

CSS では、色をトークンの変数で指す (`var(--blue)`、`var(--gray-700)`、`var(--blue-light)` など)。色の値を直接書かない。

## `:::` の記法

`::: 名前` から `:::` までが、その class を付けた枠になる。中は、ふつうの Markdown で書く。

```markdown
::: card accent
#### 見出し
- 箇条書き
:::
```

- `::: card accent` のように、空白で区切って修飾を続ける。
- `#名前` を最後に付けると、その枠に名前が付く (`::: box dark #model`)。図の線でつなぐときに使う。
- 入れ子にできる。開いた数だけ `:::` で閉じる。
- 閉じ忘れると、枠にならず、`::: card` が文字のまま出る。
- 枠はスライドをまたげない。中にスライドの区切り (`---`) や水平線は書けない。
- コードブロックの中の `:::` は、記法として扱われない。
- 同じことを HTML でも書ける (`<div class="card accent">…</div>`)。見た目は同じになる。

## card

説明をまとめる枠。見出し (`####`)、文、箇条書きを入れる。中の文字は 1 段小さくなる。

```markdown
::: grid3
::: card
#### 従来の方法
- いいね数をそのまま使う
:::
::: card warn
#### 問題
- フォロワー数に左右される
:::
::: card accent
#### 提案
- メタデータの影響を先に取り除く
:::
:::
```

| 修飾 | 見た目 | 使い道 |
|---|---|---|
| (なし) | 細い灰の枠 | 並列の項目 |
| `accent` | 青の枠 | 強調したい項目、提案 |
| `warn` | 赤の枠 | 問題、欠点 |

`square` を足すと、角丸がなくなる (`::: card square`、`::: card accent square`)。

## box

図の中の 1 つの要素。短い言葉を入れる。色で役割を示す。

| 修飾 | 役割 | 見た目 |
|---|---|---|
| (なし) | 入力、データ | 白地、濃い灰の枠 |
| `dark` | 処理、モデル | 濃い灰の地、白い文字 |
| `light` | 中間の結果 | 薄い青の地、青の枠 |
| `blue-fill` | 最終的な出力、結論 | 青の地、白い文字 |
| `warn` | 問題、否定 | 薄い赤の地、赤の枠 |
| `muted` | 未定、対象外 | 薄い灰の地、破線の枠 |

`square` を足すと、角丸がなくなる (`::: box square`、`::: box dark square #model`)。1 つの図の中では、角丸ありとなしを混ぜない。

補足の 1 行を足すには、`<span class="sub">補足</span>` を中に書く。

```markdown
::: box dark
ResNet50<span class="sub">ImageNet 事前学習</span>
:::
```

## 配置

| 名前 | 並べ方 |
|---|---|
| `row` | 横に並べる。`row center` で中央に寄せる |
| `col` | 縦に並べる |
| `grid2`、`grid3` | 等幅の 2 列、3 列 |

入れ子にできる。`row` の中に `col` を置くと、縦に積んだ組を横に並べられる。

一直線の流れは、要素の間に矢印の文字を置く。矢印は、隣の box の中心に揃う。色は `arrow blue` で青になる。

```markdown
::: row center
::: box
入力
:::
::: arrow
→
:::
::: box dark
処理
:::
:::
```

`<span class="arrow">→</span>` と書いても同じになる。これは文字を置くだけで、要素同士をつないではいない。枝分かれ、戻る線、段をまたぐ線は、次の「図の線」で引く。

## 図の線

`::: diagram` の中で、要素に名前を付け、線を 1 行に 1 本ずつ書く。

```markdown
::: diagram grid3
::: box #meta
メタデータ
:::
::: box dark #ridge
Ridge
:::
::: box light #res
残差
:::
::: box #img
画像
:::
::: box dark #resnet
ResNet50
:::
::: box blue-fill #sign
残差の正負
:::

meta -> ridge
ridge -> res
img -> resnet
resnet -> sign
res.bottom -> sign.top {blue} : 教師信号
sign.bottom -> img.bottom {dashed} : 再学習
:::
```

`::: diagram` に配置の名前を続けると (`diagram row center`、`diagram grid3`)、図そのものがその配置になる。図の中では、線を通すために、要素の間隔が広くなる。

### 線の書き方

```
出る要素.辺 -> 入る要素.辺 {指定} : ラベル
```

| 書き方 | 意味 |
|---|---|
| `a -> b` | 矢印。辺を省くと、離れている向きの、向かい合う辺が選ばれる |
| `a.right -> b.left` | 右から出て、左に入る。辺は `top`、`right`、`bottom`、`left` |
| `a -- b` | 矢じりのない線 |
| `a <-> b` | 両方向の矢印 |
| `a -> b : 再学習` | 線の上にラベルを付ける |
| `a -> b {blue}` | 青い線。ほかに `red`、`dashed`。並べて書ける (`{red dashed}`) |

線の行は、ほかの文と空行で区切る。線でない行が混ざった段落は、全体が文字として出る。

### 経路の決まり方

経路は、出る辺と入る辺の組み合わせで決まる。線は直角にだけ折れる。

| 辺の組み合わせ | 経路 |
|---|---|
| 向かい合う辺 (`right` → `left`) で、2 つの要素の範囲が重なっている | 直線。重なりの中央を通る |
| 向かい合う辺で、範囲が重なっていない | 中間で 1 回、段を付ける。同じ辺から出る線、同じ辺に入る線は、折れる位置が揃う |
| 直交する辺 (`bottom` → `left`) | L 字 |
| 同じ向きの辺 (`bottom` → `bottom`) | コの字。要素の外側を回る。戻る線に使う |

### 気をつけること

- 線は、要素やほかの線を自動でよけない。重なるときは、出る辺と入る辺を変える。
- 名前は、同じ図の中で一意にする。別の図や別のスライドの要素にはつなげない。
- 存在しない名前を指した線は描かれず、変換のときに警告が出る。
- ラベルは、線の最も長い区間の中央に置かれる。短い区間しかないと、要素に重なる。
- 斜めの線と曲線はない。
- 一直線の流れで、線を引くほどでもないときは、`::: arrow` で矢印の文字を要素の間に置く (「配置」を参照)。

## 値を変える

色、文字の大きさ、余白、角丸、線の太さは、`config/design-system/project/tokens.json` にだけ書いてある。変えたら `nh darwin switch` で反映される。テーマの CSS (`config/marp/layout.css`) と部品の CSS (`config/design-system/project/components/bundle.css`) には、値を直接書かない。
